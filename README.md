# Telegram 资源台



1. **浏览资源**：查看频道主帖及评论区媒体，按标签、关键词和类型筛选，像网盘一样整理浏览。
2. **下载媒体**：下载指定主帖或频道中的媒体，保存到本地。
3. **上传媒体**：把本地文件上传到自己频道的主帖评论区，确认成功后自动归档。

**PS：可以当做网盘来使用：上传+下载+浏览**



## 本地环境

请自行准备以下环境：

| 环境 | 要求 |
| --- | --- |
| 操作系统 | Windows x64，暂不支持 macOS |
| Java | JDK 21 |
| 原生运行库 | 匹配的 Microsoft VC++ x64 运行库 |
| 构建工具 | Maven 3.9 |
| 前端环境 | Node.js 22.12+（建议 24 LTS）、pnpm 11.25.0 |
| 视频上传 | FFmpeg、FFprobe，均需加入 PATH，用于读取视频信息和生成封面 |
| Telegram | 可用账号、API ID 和 API Hash |
| 网络 | 可连接 Telegram，支持直连、SOCKS5 或 HTTP 代理 |
| 存储 | 用于下载、待上传和上传归档的本地目录 |

数据库使用内置 SQLite，无需单独安装数据库服务。

代理连接方式可选择“使用系统代理”：每次连接或检查代理时读取 Windows 当前用户的手动代理设置，不修改系统配置，也不保存系统代理地址的副本。支持单一 HTTP 地址及按协议配置的 HTTP / SOCKS5 地址；系统未启用手动代理时使用直连。修改系统代理后，请断开并重新连接 Telegram。暂不支持 PAC、自动检测（WPAD）和系统代理认证；PAC 配置会明确报错，需认证时请使用手动 HTTP / SOCKS5 配置。

| 传输偏好 | 保存默认下载目录和 1～4 个文件的下载并发数；并发在下一下载任务生效，上传仍按组发送。已有任务和规则保留创建时的目录及策略。 |
| Windows 托盘 | 可在“设置 → 传输与存储”启用托盘图标，关闭网页后从托盘返回或正常退出；默认关闭，不设置开机启动。 |

## 使用范围

- 资源库与上传目标限自己创建或管理的频道；下载来源可为当前账号有权访问且允许保存的外部频道。
- 标签和关键词只匹配主帖文字；主帖附件与评论媒体分别控制。
- 下载日期范围仅用于频道历史扫描，按主帖发布时间的北京时间日期判断，包含起止当天，单边留空表示该侧不限；不按评论发布时间筛选。发布时间未知的主帖会提示待核实，不会自动计为匹配或加入批量下载。修改筛选后需重新扫描，已有批次保留原筛选快照；指定单帖、机器人和持续规则不应用该日期草稿。
- 频道、批量、单帖、机器人及自动规则下载均不设累计主帖数、媒体数或翻页次数的业务上限。每次网络读取、界面分页和内部工作分片仍有界；批量创建按每100个媒体拆分内部子任务，不限制总任务数。单次请求超时、机器人回复等待及会话过期仍需按提示处理。用户停止后保存当前位置；账号变化、网络结果不明或范围校验失败时需核对后继续，不会重复提交未知的创建请求。
- 旧资源索引未保存真实发布时间时显示“发布时间未知”，读取更新后补齐；索引更新时间不作为发布日期。
- 浏览器缩略图缓存限当前标签页会话，刷新或关闭页面后重新建立；后端磁盘缓存仍可复用。正常缩略图最多复用10分钟，低清或暂无预览仅短暂缓存30秒，读取异常不缓存。账号切换、授权退出、索引更新以及保存或清理缩略图设置会作废旧缓存和旧请求；设置中的清理同时作用于页面内存与本应用自有磁盘缓存。
- 上传字节完成仍需正式回执及归档，下载字节完成仍需校验保存。速度和剩余时间仅在有新鲜、有效采样时显示；暂停、停滞或剩余量未知时不推断。
- 自动规则需要后台运行并连接 Telegram；关机或完全退出期间不执行。
- 上传规则的检测和启用前预览在后台准备，页面仅更新准备状态；停止等待后可核对原结果，不会重复提交或自动启用上传。
- 进入页面时读取最新数据，也可手动刷新；返回任务中心时收起详情，保留已加载记录，后台执行不依赖页面是否打开。
- 上传结果不明时先核对，不直接整组重发；下载和索引状态以已确认的读取范围为准。
- 网络超时、暂时断线、Telegram 服务暂时不可用或连续两分钟没有进展时，下载会保留原任务与进度。单个文件暂时失败后，本轮继续处理其余文件，结束后对未完成项自动重试；已完成文件不重复下载。首次自动重试等待5分钟，再次失败后每半小时重试，不设次数上限；Telegram明确要求更长的限流等待时遵守其等待时间。原文件按连续可读区间逐块写入并校验本地断点，重试或重启后从已保存的字节位置继续；原生缓存丢失也不重写已校验的目标前缀。自有停滞缓存只取消当前传输并保留部分字节，并发组内有文件持续增长时不会把排队文件误判为停滞。任务中心显示重试次数和预计北京时间，后台执行不依赖网页打开。手动暂停、整批暂停、全部暂停或删除会取消对应重试，手动暂停的任务必须显式继续；规则任务同时遵守启用状态与执行时段。文件身份变化、权限及磁盘校验错误仍需处理。
- 机器人媒体在实际开始下载前会重新核对可读的原消息；原消息已不可读时可尝试之前已保存的准确文件引用。程序跟踪实际下载的最终回执，失败后仅在核对同一文件身份和大小后刷新并重试一次；不能刷新时保留断点并明确提示，不会把启动回执或离线文件身份当成下载成功。所有字节保存后仍需等待最终回执及完整文件校验；未确认的完整断点在重试、重启后也不会提前发布。原消息不可读取且旧引用已被拒绝时，需要机器人重新提供有效媒体来源。
- 已暂停的独立下载任务可在任务中心点击“删除”，确认后移除任务记录并禁止继续。已经保存的文件保留；后台只清理能确认归属的未完成临时文件及未被其他任务使用的自有缓存。删除不清除下载成功与去重凭据，重复提交同一次删除也不会重建任务。运行中任务需先暂停并等待停稳；批量或规则所属的子任务不提供单独删除。
- 机器人下载位于“新建传输 → 下载 → 机器人下载”。在 Telegram 打开起始页／组，填写机器人用户名或已有私聊 ID，保留默认的“自动翻页采集至末页”，点击“读取当前页／组”。程序读取本次回复并等待稳定后自动翻下一页，同时保留已观察媒体的原文件引用，翻页不等待文件内容下载，避免耗尽分页按钮的有效时间。采集到末页或手动停止后，勾选媒体和保存目录，点击“下载选中媒体”创建后台任务。取消勾选自动采集可只读取当前页，也可手动翻页继续采集。
- 自动采集需要保留当前面板；停止、断线或离开面板后不再点击下一页，已读取的媒体仍保留。下载任务创建后由后台独立执行，不依赖原预览继续打开。文件引用与明确观察到的媒体身份一起保存在本地任务中；下载时优先核对并使用已保留的文件引用，原消息暂时不可读取时不直接拒绝已观察的文件。引用确实失效且无法恢复时，任务会给出重新获取文件的提示。仅采集当前请求范围，不自动遍历旧聊天历史；数字“下 10 页”按页码窗口处理，末页判断与文件实际保存完成分别展示。
- 机器人“当前批次发送完成”仍可能有下一组；“文件夹内容发送完成”才作为整体结束提示。“26/38 条消息”和“1–26/38 跳转”不作为页码，范围跳转、文件夹详情、列表等按钮不作为翻页入口。
- 机器人翻页后默认先等 5 秒，再检查回复；新媒体或分页信息连续 5 秒没有变化后，才允许继续翻页。稳定等待可设为 2～60 秒，最长等待默认 120 秒、可设为 15～300 秒；超时可点击“继续等待”，不会重复按分页按钮。慢速分批回复可适当延长缓冲，稳定等待不代表所有媒体均已送达。
- 翻页请求已记录但回执未确认时，会继续只读核对回复；确认分页或媒体已变化并经过稳定等待后继续采集下一页，不会重复发送原回调。遇到等待超时、请求失败、连接中断、重复位置或无法可靠识别下一页时停止；恢复连接或刷新消息不会自动重启已停止的采集。创建任务时只接受本次明确观察到且经过文件身份校验的媒体，不把未知文件加入队列。
- 机器人支持普通内联回调分页及未识别按钮的手动确认；URL 跳转、付款、密码回调和回复键盘暂不支持。翻页结果不明时只刷新回复核对；预览媒体数、单个下载任务的媒体数和翻页次数不设固定上限。预览在重启或闲置 10 分钟后失效，已创建的下载任务仍保留。
- 点击“下载选中媒体”后，机器人文件会在后台分批核对，全部核对完成后创建下载任务；大批量准备不再受整批 60 秒时限影响，也不占用翻页读取。页面自动查询原准备结果，“停止等待”只停止页面查询，后台仍会继续准备和创建任务；点击“核对创建结果”可继续查询，不会再次提交。准备失败保留勾选和目录，并提示缺失、变化或读取失败的文件／批次，便于调整后重试。项目退出会停止尚未完成的准备，已创建任务仍保留。

## 构建与启动

### 方式一：双击运行（推荐）

配置好上述本地环境及 `JAVA_HOME`、Maven、PATH 后，在项目文件夹中：

1. **首次使用或更新代码后**：双击 `build.cmd`，等待构建完成，确认没有报错。已有后台运行时，先关闭项目再构建。
2. **日常启动**：双击 `start.cmd`，自动启动后台并打开页面，无需每次构建。首次使用在页面“设置”中连接 Telegram。
3. **退出项目**：在页面“设置”顶部点击“关闭项目”。仅关闭浏览器页面不会退出后台。

这两个文件分别调用 `scripts/build.ps1` 和 `scripts/start.ps1`，自动设置本次 PowerShell 进程的执行策略，不修改系统的永久策略。运行报错时窗口会停留，便于查看原因。

### 方式二：PowerShell 命令

以下命令在 **PowerShell** 中执行。示例项目目录为 `D:\temp\TelegramEnhance`，请替换为自己的实际路径。

#### 1. 进入项目目录

```powershell
Set-Location 'D:\temp\TelegramEnhance'
```

当前目录应包含 `pom.xml`、`frontend` 和 `scripts`。

#### 2. 检查本地环境

自行配置环境后，确认以下命令均可执行：

```powershell
$env:JAVA_HOME
java -version
mvn -v
node -v
pnpm -v
ffmpeg -version
ffprobe -version
```

版本应符合上方环境要求。提示“找不到命令”时，先检查对应工具及 PATH 配置。

找不到 `node` 或 `npm` 时，先安装 [Node.js](https://nodejs.org/en/download)（Windows x64），安装时保留加入 PATH 的选项。重新打开 PowerShell，再安装项目使用的 pnpm：

```powershell
npm.cmd install --global pnpm@11.25.0
pnpm.cmd -v
```

pnpm 仍找不到时，执行 `npm.cmd config get prefix`，将输出的目录加入用户 PATH，再重新打开终端或项目文件夹。构建脚本会先检查所需命令；它不会自动安装环境。请在普通 Windows PowerShell 中检查，编辑器终端内可用的工具不一定在双击脚本时可用。

脚本默认读取环境变量 `JAVA_HOME`，应指向本机 **JDK 21 的安装根目录**，不是 `bin` 目录。配置好后，以下命令都不需要填写 Java 路径。

`-JavaHome` 仅用于临时指定其他 JDK，参数值填写该电脑实际的安装目录，不是固定路径。

#### 3. Maven 配置

本项目使用本机已安装并配置好的 Maven。构建入口为 `scripts/build.ps1`，相关参数在脚本顶部：

- `MavenHome`：指定本机 Maven 安装目录，默认读取 `MAVEN_HOME`；未设置时依次使用 `M2_HOME`、PATH。
- `MavenSettings`：可选，指定本机的 `settings.xml`；留空时使用 Maven 默认配置。

Maven 的安装、仓库和镜像等由使用者自行配置。

#### 4. 首次构建

```powershell
.\scripts\build.ps1
```

脚本会依次安装前端依赖、运行前端测试、构建前端、编译并测试后端，最后生成运行文件。首次构建需要联网下载依赖，出错时会停止。

看到 Maven 输出 `BUILD SUCCESS` 且脚本没有报错后，检查以下产物：

| 路径 | 内容 |
| --- | --- |
| `target/telegram-resource-workbench-0.1.0-SNAPSHOT.jar` | 主程序及构建后的前端页面 |
| `target/lib/` | 运行所需的依赖和原生库 |

运行时两者都要保留。日常启动无需重复构建。

#### 5. 启动项目

```powershell
.\scripts\start.ps1
```

脚本会在后台启动 Java，并打开本机页面。首次使用在“设置”中配置并授权 Telegram；以后启动后台会自动连接已保存的会话，连接失败时可在设置中手动重试。

- 页面使用 `127.0.0.1` 随机端口，每次启动可能不同。
- 再次运行启动脚本会复用已有后台，并重新打开页面。
- 请通过启动脚本进入页面，不要固定使用上次的端口地址。
- 主动断开后，本次运行不会自动重连；注销会话后需要重新授权。

只启动后台、不自动打开页面时：

```powershell
.\scripts\start.ps1 -NoBrowser
```

#### 6. 正常退出

在页面“设置”顶部点击“关闭项目”，或执行：

```powershell
.\scripts\stop.ps1
```

脚本显示“已请求安全退出”后，后台开始保存并关闭，Telegram 会话保留。关闭浏览器标签页只关闭界面，后台仍可能继续执行任务。

可用以下命令检查退出标识：

```powershell
Test-Path '.\data\runtime.json'
```

输出 `False` 表示运行标识已移除；等待后台退出后，再更新程序文件或重新构建。

#### 7. 修改代码或更新后的重建

先退出旧后台：

```powershell
.\scripts\stop.ps1
```

确认后台已退出后，执行：

```powershell
.\scripts\build.ps1
.\scripts\start.ps1
```

构建成功后再启动；构建失败时先处理错误。只刷新浏览器不会构建或加载尚未打包的新代码。

应用数据默认保存在项目内的 `data` 文件夹，更新项目时保留该目录：

| 路径 | 内容 |
| --- | --- |
| `data/metadata.sqlite` | SQLite 数据库，保存设置、资源库、任务与规则 |
| `data/telegram/` | Telegram 登录会话及原生缓存 |
| `data/backups/` | 数据库结构升级时的备份 |

移动项目时一起保留 `data`；凭据受 Windows 当前用户保护，复制到另一台电脑或另一个 Windows 账号后需重新配置授权。下载文件和上传归档仍保存在各任务指定目录。

## 常见构建与启动问题

| 情况 | 处理方式 |
| --- | --- |
| 找不到 `java`、`mvn` 或 `node` | 检查本地安装与 PATH；重新打开 PowerShell 后再检查。 |
| 找不到 `pnpm` | 先安装 Node.js，再执行 `npm.cmd install --global pnpm@11.25.0`；确认 npm 全局命令目录在 PATH 中。 |
| Java 版本不符 | 检查 `JAVA_HOME` 是否指向本机 JDK 21 的根目录；重新打开 PowerShell 后再检查。 |
| PowerShell 提示禁止运行脚本 | 改用项目根目录的 `build.cmd` 或 `start.cmd`。 |
| 依赖下载失败 | 检查网络能否访问 Maven Central、MCHV 和前端依赖仓库，恢复后重新构建。 |
| 提示先运行 `scripts/build.ps1` | 双击 `build.cmd` 或完成命令行第 3 步，确认 JAR 和 `target/lib` 已生成。 |
| 页面提示从启动脚本打开 | 双击 `start.cmd` 或重新运行 `scripts/start.ps1`，使用它打开的新页面。 |
| 构建提示文件被占用 | 先正常退出本项目后台，等待退出完成后再构建。 |
| 后台启动失败或原生库加载失败 | 查看下面的日志；检查 JDK、完整的 `target/lib` 和匹配的 Windows x64 VC++ 运行库。 |

启动日志位于：

```text
data\backend.log
data\backend-error.log
```

## 本地视频工具

项目根目录另附两个独立的 Windows 脚本，仅处理指定目录当前层的视频，保留原件，不接入 Telegram 任务或自动规则：

| 脚本 | 用途与依赖 |
| --- | --- |
| `剪去视频开头.cmd` | 按指定秒数剪去开头，结果放入 `out`，同名结果跳过。需要 FFmpeg、FFprobe；默认无损模式向后对齐关键帧，可能额外剪掉一些内容；`-Mode Exact` 显式选择 H.264/AAC 有损重编码。 |
| `拆分大视频.cmd` | 超过 2000MB 时优先分为两份，任一仍超限则按每份不超过 1900MB 分为多个 `part`，结果放入 `out`；验证成功后将原视频移入同级“大视频”目录。需要 Python 3.10+、FFmpeg、FFprobe；已内嵌 Python 脚本，不依赖本机 Skill 目录。大小按 Windows 显示口径（MiB，1MB = 1,048,576 字节）计算。 |

```powershell
.\剪去视频开头.cmd -Seconds 3 -Directory 'D:\视频'
.\拆分大视频.cmd -Directory 'D:\视频'
```

工具可放在脚本旁、加入 PATH，或通过 `-FFmpeg`、`-FFprobe` 指定完整路径；分割脚本另支持 `-Python`。裁剪脚本验证开头 8 帧，不进行全片解码；分割脚本执行大小、完整帧/包覆盖与独立解码检查。处理结束后请按各脚本报告核对结果。
