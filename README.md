# Telegram 资源台



1. **浏览资源**：查看频道主帖及评论区媒体，按标签、关键词和类型筛选，像网盘一样整理浏览。
2. **下载媒体**：下载指定主帖或频道中的媒体，保存到本地。
3. **上传媒体**：把本地文件上传到自己频道的主帖评论区，确认成功后自动归档。

**PS：可以当做网盘来使用：上传+下载+浏览**



## 本地环境

请自行准备以下环境：

| 环境 | 要求 |
| --- | --- |
| 操作系统 | Windows x64，暂不支持 macOS |
| Java | JDK 21 |
| 原生运行库 | 匹配的 Microsoft VC++ x64 运行库 |
| 构建工具 | Maven 3.9 |
| 前端环境 | Node.js 22.12+、pnpm 11 |
| Telegram | 可用账号、API ID 和 API Hash |
| 网络 | 可连接 Telegram，支持直连、SOCKS5 或 HTTP 代理 |
| 存储 | 用于下载、待上传和上传归档的本地目录 |

数据库使用内置 SQLite，无需单独安装数据库服务。

## 功能列表

| 模块 | 功能 |
| --- | --- |
| Telegram 连接 | 账号授权、启动时自动连接已保存会话、独立代理、断开与注销。 |
| 关闭项目 | 设置页顶部一键正常关闭后台，保留设置、任务记录及 Telegram 会话。 |
| 我的资源库 | 导入自己创建或管理的频道及主帖；按频道、标签和关键词搜索；浏览主帖、相册和评论媒体。 |
| 媒体预览 | 列表与卡片展示、滚动加载、类型筛选、图片与视频缩略图、跳转 Telegram 原消息。 |
| 下载 | 单帖下载、频道扫描与批量下载；支持主帖附件和评论媒体；暂停、继续及进度恢复。 |
| 重复媒体处理 | 根据数据库历史、来源信息、文件大小和 SHA-256 判重；新下载任务将重复文件单独保存到“重复媒体”目录。 |
| 上传 | 支持图片、视频、音频、文档等文件；不同类型分别分组，每组最多 10 个，GIF 单独处理。 |
| 上传归档与恢复 | 整组正式成功回执核对完整后归档；保留成功成员，核对未决结果，仅重试可重试的失败成员或归档操作。 |
| 自动下载 | 按频道标签、关键词筛选，或跟踪指定主帖；扫描历史、发现新帖、补扫旧帖新增评论媒体。 |
| 自动上传 | 持续检测目录中的新增稳定文件，自动分组上传并归档，跳过已处理的重复内容。 |
| 任务中心 | 分类查看单帖下载、频道批量下载及上传任务；列表手动刷新，运行任务局部更新进度，查看文件位置和异常状态。 |
| 执行时段 | 支持全天或指定北京时间窗口，支持跨午夜，以及规则启用、暂停和重启恢复。 |
| 缩略图缓存 | 本地持久缓存、重启复用、自定义保存位置、一键清理；最多 4096 张、256MB。 |

## 使用范围

- 资源库与上传目标限自己创建或管理的频道；下载来源可为当前账号有权访问且允许保存的外部频道。
- 标签和关键词只匹配主帖文字；主帖附件与评论媒体分别控制。
- 自动规则需要后台运行并连接 Telegram；关机或完全退出期间不执行。
- 任务与规则列表由用户刷新；后台执行不依赖页面是否打开。
- 上传结果不明时先核对，不直接整组重发；下载和索引状态以已确认的读取范围为准。

## 构建与启动

### 方式一：双击运行（推荐）

配置好上述本地环境及 `JAVA_HOME`、PATH 后，在项目文件夹中：

1. **首次使用或更新代码后**：双击 `build.cmd`，等待构建完成，确认没有报错。已有后台运行时，先关闭项目再构建。
2. **日常启动**：双击 `start.cmd`，自动启动后台并打开页面，无需每次构建。首次使用在页面“设置”中连接 Telegram。
3. **退出项目**：在页面“设置”顶部点击“关闭项目”。仅关闭浏览器页面不会退出后台。

这两个文件分别调用 `scripts/build.ps1` 和 `scripts/start.ps1`，自动设置本次 PowerShell 进程的执行策略，不修改系统的永久策略。运行报错时窗口会停留，便于查看原因。

### 方式二：PowerShell 命令

以下命令在 **PowerShell** 中执行。示例项目目录为 `D:\temp\TelegramEnhance`，请替换为自己的实际路径。

#### 1. 进入项目目录

```powershell
Set-Location 'D:\temp\TelegramEnhance'
```

当前目录应包含 `pom.xml`、`frontend` 和 `scripts`。

#### 2. 检查本地环境

自行配置环境后，确认以下命令均可执行：

```powershell
$env:JAVA_HOME
java -version
mvn -v
node -v
pnpm -v
```

版本应符合上方环境要求。提示“找不到命令”时，先检查对应工具及 PATH 配置。

脚本默认读取环境变量 `JAVA_HOME`，应指向本机 **JDK 21 的安装根目录**，不是 `bin` 目录。配置好后，以下命令都不需要填写 Java 路径。

`-JavaHome` 仅用于临时指定其他 JDK，参数值填写该电脑实际的安装目录，不是固定路径。

#### 3. 首次构建

```powershell
.\scripts\build.ps1
```

脚本会依次安装前端依赖、运行前端测试、构建前端、编译并测试后端，最后生成运行文件。首次构建需要联网下载依赖，出错时会停止。

看到 Maven 输出 `BUILD SUCCESS` 且脚本没有报错后，检查以下产物：

| 路径 | 内容 |
| --- | --- |
| `target/telegram-resource-workbench-0.1.0-SNAPSHOT.jar` | 主程序及构建后的前端页面 |
| `target/lib/` | 运行所需的依赖和原生库 |

运行时两者都要保留。日常启动无需重复构建。

#### 4. 启动项目

```powershell
.\scripts\start.ps1
```

脚本会在后台启动 Java，并打开本机页面。首次使用在“设置”中配置并授权 Telegram；以后启动后台会自动连接已保存的会话，连接失败时可在设置中手动重试。

- 页面使用 `127.0.0.1` 随机端口，每次启动可能不同。
- 再次运行启动脚本会复用已有后台，并重新打开页面。
- 请通过启动脚本进入页面，不要固定使用上次的端口地址。
- 主动断开后，本次运行不会自动重连；注销会话后需要重新授权。

只启动后台、不自动打开页面时：

```powershell
.\scripts\start.ps1 -NoBrowser
```

#### 5. 正常退出

在页面“设置”顶部点击“关闭项目”，或执行：

```powershell
.\scripts\stop.ps1
```

脚本显示“已请求安全退出”后，后台开始保存并关闭，Telegram 会话保留。关闭浏览器标签页只关闭界面，后台仍可能继续执行任务。

可用以下命令检查退出标识：

```powershell
Test-Path '.\data\runtime.json'
```

输出 `False` 表示运行标识已移除；等待后台退出后，再更新程序文件或重新构建。

#### 6. 修改代码或更新后的重建

先退出旧后台：

```powershell
.\scripts\stop.ps1
```

确认后台已退出后，执行：

```powershell
.\scripts\build.ps1
.\scripts\start.ps1
```

构建成功后再启动；构建失败时先处理错误。只刷新浏览器不会构建或加载尚未打包的新代码。

应用数据默认保存在项目内的 `data` 文件夹，更新项目时保留该目录：

| 路径 | 内容 |
| --- | --- |
| `data/metadata.sqlite` | SQLite 数据库，保存设置、资源库、任务与规则 |
| `data/telegram/` | Telegram 登录会话及原生缓存 |
| `data/backups/` | 数据库结构升级时的备份 |

移动项目时一起保留 `data`；凭据受 Windows 当前用户保护，复制到另一台电脑或另一个 Windows 账号后需重新配置授权。下载文件和上传归档仍保存在各任务指定目录。

## 常见构建与启动问题

| 情况 | 处理方式 |
| --- | --- |
| 找不到 `java`、`mvn`、`node` 或 `pnpm` | 检查本地安装与 PATH；重新打开 PowerShell 后再检查。 |
| Java 版本不符 | 检查 `JAVA_HOME` 是否指向本机 JDK 21 的根目录；重新打开 PowerShell 后再检查。 |
| PowerShell 提示禁止运行脚本 | 改用项目根目录的 `build.cmd` 或 `start.cmd`。 |
| 依赖下载失败 | 检查网络能否访问 Maven Central、MCHV 和前端依赖仓库，恢复后重新构建。 |
| 提示先运行 `scripts/build.ps1` | 双击 `build.cmd` 或完成命令行第 3 步，确认 JAR 和 `target/lib` 已生成。 |
| 页面提示从启动脚本打开 | 双击 `start.cmd` 或重新运行 `scripts/start.ps1`，使用它打开的新页面。 |
| 构建提示文件被占用 | 先正常退出本项目后台，等待退出完成后再构建。 |
| 后台启动失败或原生库加载失败 | 查看下面的日志；检查 JDK、完整的 `target/lib` 和匹配的 Windows x64 VC++ 运行库。 |

启动日志位于：

```text
data\backend.log
data\backend-error.log
```
